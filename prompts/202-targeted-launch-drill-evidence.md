# 202 — targeted launch drill evidence without synthetic production claims

## Scope and why this is next

The committed baseline is `411ba0c` on `main`. Prompt 201 describes the remaining Phase 12 operator sign-off but has **not** been executed. Its own execution notes identify a prerequisite defect: Stage 3 of `scripts/ops/run-launch-drills.sh` always verifies the example Caddyfile and default deployment configuration, while Stage 6 omits the capacity target and therefore runs a synthetic benchmark even when the orchestrator is invoked without `--dry-run`. Inspection also found that `scripts/ops/run-capacity-alerting-drill.sh` fabricates passing PostgreSQL exporter, pool, query, and lock telemetry when live benchmarking returns no database latency data. These outputs must not be eligible for production approval. This prompt is a Phase 12 dependency-safe remediation before returning to prompt 201; it does not repeat or replace human launch sign-off.

## Expected files and behavior

Use names consistent with the child commands (`--caddyfile`, `--compose-file`, `--target-url`, `--api-url`), document them in `--help`, and reject missing/empty option values before creating an evidence directory or starting any stage. Reject `--dry-run` combined with live target arguments rather than silently ignore them. Keep the current no-argument offline behavior for CI. Forward values as argument arrays or an equally safe mechanism: never interpolate operator-controlled paths/URLs into the current `bash -c "$*"` stage string. Preserve spaces and shell metacharacters as literal data, and avoid echoing credential-bearing URLs. Consider refactoring `run_stage` to execute argument vectors instead of a shell string; protect the existing multi-command stages without introducing `eval` or untrusted shell parsing.
2. **Evidence identity.** A non-dry-run invocation without explicit targets is a *drill/default* run, not a production run. Do not set dossier `environment: "production"` solely from absence of `--dry-run`. Record which Caddyfile, Compose file, and benchmark/API targets were used with redacted or hashed identifiers that contain no URL userinfo, query tokens, or secret values. Keep the dossier format and consumers backward compatible where possible; if a version bump is needed, update the validator and docs together. Operator-specified targets may be checked as live target evidence only when their corresponding child reports verify the same target and live mode. This remains evidence of a drill, not proof of a production promotion or human approval.
3. **Stage 3 fail-closed binding.** Pass the same Caddyfile to `verify-caddy-routing.js` and `run-deployment-drill.sh`, and the selected Compose file to the deployment drill. Validate that the deployment child refers to the selected files and does not claim live readiness when its probe fell back to static inspection. A Stage 3 child that fails, is missing, or targets a different file breaches the dossier regardless of process exit status. The script must not execute a live promotion/rollback just because a target is passed; inspect the child behavior and keep any mutation behind its existing operator authorization boundary.
4. **Stage 6 fail-closed binding.** Pass `--target-url` and `--api-url` to `run-capacity-alerting-drill.sh` in live-target mode. Synthetic mode may retain clearly marked synthetic data for deterministic CI tests; live mode must instead consume independently captured API/worker pool, PostgreSQL exporter/server, query, and lock telemetry from an explicit operator-provided evidence input or a verified live telemetry collector. Validate source, timestamp freshness relative to the drill, required metric fields, numeric bounds, target identity, and probe health; absence, malformed input, stale telemetry, or failed scrape must produce `databaseTelemetryBaseline.status: "breached"` and nonzero live-stage result. Alert simulation is still a simulation; label it accurately and leave live alert-delivery verification to the operator.
5. **Dossier aggregation.** Derive Stage 3 and Stage 6 summary fields from validated child content, not solely child exit codes. Keep failures visible in `stages[].error_message`, baseline status, and `summary`. A seven-stage process pass cannot hide a mismatched, synthetic, or missing child report. ## Security, failure, and compatibility cases

- Reject missing option values, invalid schemes, URL userinfo, fragment/query secrets, an example Caddyfile offered as production evidence, mixed target identities, failed child JSON, and malformed/nonfinite metric values. Bound any new file input and use safe path handling. Do not write or print credentials in command lines, `--verbose`, logs, dossier, or git.
- A live benchmark can send traffic and a DoS drill can exercise throttling. Tests must use local fixtures or controlled loopback targets; actual operator environments and any production load require a concrete approved target and window during prompt 201. The present implementation prompt authorizes code and isolated test fixtures only.
- Preserve existing dry-run tests and CLI defaults. If a formerly green synthetic child is no longer accepted as live evidence, document that deliberate fail-closed behavior. No new database migration, product API, UI, provider, deployment, live secret rotation, or production approval is in scope.
- Rollback is the single implementation commit revert if no evidence format has been adopted externally. If evidence consumers need a schema/version change, maintain a migration note and accept old files only as non-production historical drill records.
