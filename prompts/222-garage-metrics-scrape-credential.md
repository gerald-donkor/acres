# 222 — Garage metrics scrape credential

## Scope and why this is next

Phase 12K remains open because its launch categories require operator evidence. Prompt 221 gave `csrf_secret_source` a distinct API consumer. The next repository-verifiable Category 4 gap is `garage_metrics_secret_source`: production Compose injects `GARAGE_METRICS_TOKEN` into Garage, but the checked-in Garage configuration does not explicitly require token authentication and Prometheus has no Garage scrape. Wire one operator-owned metrics credential file to Garage and Prometheus, configure an authenticated private scrape, and make template checks reject a broken or exposed path. This prepares credible secret-reference and telemetry evidence; it does not approve either launch category.

## Implementation contract

1. Use **one** operator-owned credential file as the source for both Garage's metrics verifier and Prometheus's bearer authorization. Add a required absolute host-file input such as `ACRES_GARAGE_METRICS_TOKEN_FILE` to the production environment template with an unresolved operator placeholder. Mount that file read-only at `/run/secrets/garage_metrics_token` in exactly the `garage` and `prometheus` services. Configure Garage's verified file input, `GARAGE_METRICS_TOKEN_FILE`, to read its mount. Remove the existing plaintext `GARAGE_METRICS_TOKEN` Compose/env-file injection so an old independent value cannot disagree with the scraper. Retain distinct `GARAGE_RPC_SECRET` and `GARAGE_ADMIN_TOKEN` inputs on Garage only. State operator file ownership, mode, and both container-reader requirements without inventing the Garage image UID; verify it from the pinned image or instruct the operator to check it. Never commit, print, or bake a real token into a config, command line, image, log, or test fixture.
2. Set `[admin].metrics_require_token = true` in the effective production Garage configuration. Keep the admin listener private at port 3903 and leave the existing unauthenticated `/health` readiness probe functional. If the shared TOML would change local development behavior, document and test that effect; use a production-specific TOML only if the shared config cannot satisfy both environments safely. Do not introduce a second token source or embed a placeholder token in TOML.
3. Add an `acres-garage` Prometheus scrape for `garage:3903`, path `/metrics`, using `authorization.credentials_file: /run/secrets/garage_metrics_token` (or the equivalent verified syntax). Do not use inline `authorization.credentials`, a query parameter, the Garage admin token, a public Caddy route, or a new externally published port. Prometheus and Garage remain on the existing private network. Scrape failure must surface through `up{job="acres-garage"}`. Do not assert any Garage-specific metric name until observed from pinned Garage; this step needs authenticated scrape health, not a speculative capacity dashboard or threshold.

Add focused negative tests by mutating parsed template fixtures; cover the valid configuration and each meaningful failure path. ## Expected impact, limits, and rollback

- The only expected runtime changes are Garage metrics authentication and Prometheus's private Garage scrape. There is no product route, browser UI, database schema, GraphQL contract, worker queue, or new service. Existing Caddy/S3 paths and Garage admin operations stay separate from the metrics token. Garage metrics ingestion may add time series, so check cardinality and storage behavior before assigning new retention or alert thresholds.
- Existing materialized production configs must be updated together: provide the restricted file, mount it in Garage and Prometheus, remove the old `GARAGE_METRICS_TOKEN` injection, and reload/restart the affected containers in the operator's deployment window. A mismatched or unreadable file makes the scrape fail closed; document how to inspect target state without revealing the bearer. Token rotation requires updating the shared source and reloading/restarting both consumers, followed by an authenticated scrape check. Do not carry out production access, promotion, or rotation under this prompt.
- Rollback restores the prior Garage/Prometheus configuration and removes the new scrape/file mounts together. It reopens the unused Category 4 source gap and does not turn launch status green. Keep the file protected during and after rollback until the operator revokes it.
