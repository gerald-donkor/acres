# 220 — scope production API and worker environment

## Scope and why this is next

Phase 12K remains the earliest unfinished phase. At `7c8c74b5f91effc534b64a2f502a160d9736a1db` on `main`, prompt 219 removed the shared production `env_file` from Caddy and Next, but both `api` and `worker` still import `infra/env/production.env.example` wholesale. That file contains database superuser and migrator credentials, Grafana credentials, release image inputs, host mount paths, Caddy settings, backup/retention/alert decisions, and other values unrelated to either Node process. The remaining API/worker injection is a concrete repository defect that can be fixed and verified offline while the operator handoff and prompt 201 launch sign-off remain blocked on real production evidence.

Make the production Compose example give each Node service only the inputs it actually consumes. Retain the operator's one materialized input source for Compose interpolation; remove service-level `env_file` for `api` and `worker` and use explicit `environment` maps, as prompt 219 did for Caddy and Next. Add a parsed, fail-closed template contract and focused negative tests. Document the operator migration and the limits of repository verification. This prompt is scoped to the **API/worker service environment boundary**, not to resolving every Category 4 finding.
