# 169 — expose and scrape worker PostgreSQL pool telemetry

## Scope and why this is next

The committed baseline is `f3413c2` on `main`, with a clean worktree when this prompt was prepared. Phase 12 in `docs/build-plan.md` requires DB/query/pool observability. Prompt 168 exposed the API process's `pg.Pool` counts, and `docs/operations.md` explicitly leaves the worker pool unseen. The next dependency-safe unit is to expose the **existing worker process's own metrics registry** on a private listener, scrape it as a separate Prometheus job, and show its pool counts separately from the API. This also makes existing worker queue/parser counters observable. Do not infer whole-PostgreSQL saturation or add a threshold from these process-local snapshots.

## Behavior, failure cases, and rollout

- The worker listener is internal operational infrastructure. It must not be routed by Caddy, exposed to browsers, or require an API session. Private Compose network placement is its access boundary; tests must reject accidental host publication. A local default loopback bind should avoid exposing it on a developer's LAN.
- A scrape must not start work or connect solely to read the pool. After successful worker startup, `/health` is an operational process/readiness probe as documented; `/metrics` may fail when its collector fails. Failed scrapes should yield Prometheus `up=0` for the worker target, not retained healthy-looking pool data. On shutdown, stop accepting new scrapes and close the listener while completing the existing job drain and Nest close path.
- The existing API `/metrics`, business routes, auth/RLS, worker queue semantics, database schema, and pool configuration retain behavior. Neither a worker `waiting > 0` sample nor a full pool alone proves PostgreSQL server saturation. Production capacity evidence is still required for any pool alert threshold.
- Rollback removes the worker listener/scrape/panels/healthcheck override and restores prior alert/dashboard selectors only if the second target is gone. The worker returns to unobserved pool and queue counters; note the pre-existing image healthcheck limitation if rolling back to the previous worker topology.
